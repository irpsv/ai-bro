# Create Release

Твоя задача — выпустить уже зафиксированную версию плагина: создать git-тег и GitHub Release с описанием.

Вызов и есть согласие публиковать. Повторно разрешение не спрашивай.

## ОБЩИЕ ПРАВИЛА

- **ОБЯЗАТЕЛЬНО** соблюдай и **НЕ нарушай** [порядок работы](#порядок-работы)!
- Релиз только с текущего коммита ветки `main`. Другие ветки, pull request и то, влита ли версия, не разбирай.
- Версия — одно значение semver `X.Y.Z` в трёх полях: `version` в `plugin.json`, `version` в `.cursor-plugin/plugin.json`, `metadata.version` в `.cursor-plugin/marketplace.json`.
- Имя тега и заголовок релиза равны этой версии, без префикса `v`.
- В описание попадают только каталоги `skills/<имя>/`. Правки вне скиллов в разделы не выноси.

## ОГРАНИЧЕНИЯ / STOP

- **ЗАПРЕЩЕНО** повышать версию, править манифесты, скиллы и любые другие файлы.
- **ЗАПРЕЩЕНО** переключать ветку, мержить, пушить ветку `main` и делать force push.
- **ЗАПРЕЩЕНО** создавать тег или релиз, пока любая проверка из шага 1 не пройдена.
- **ЗАПРЕЩЕНО** удалять, переименовывать и перезаписывать теги и релизы.
- **ЗАПРЕЩЕНО** менять git config и использовать `--force`, `--amend`, `--no-verify`.

## ПОРЯДОК РАБОТЫ

1. **ПРОВЕРЬ** условия. Любое невыполненное — остановись и назови его. Ничего не создавай.
   - Текущая ветка — `main`.
   - Рабочее дерево чистое: нет незакоммиченных и неотслеживаемых файлов.
   - Три поля версии есть и равны между собой, формат `X.Y.Z`.
   - `origin` — GitHub. Из URL возьми `owner/repo`.
   - `gh` авторизован в этом репозитории.
   - Локального тега, тега на `origin` и GitHub Release с этой версией нет.
2. **СОБЕРИ** описание по [формату](#формат-описания). Предыдущий тег — наибольший тег вида `X.Y.Z`, кроме текущей версии. Нет такого тега — предыдущего нет.
3. **СОЗДАЙ** легковесный тег на `HEAD` с именем версии и запушь только этот тег на `origin`.
4. **СОЗДАЙ** GitHub Release с заголовком версии и собранным описанием. Релиз сразу опубликованный, не черновик.
5. **ПОКАЖИ** версию, тег и URL релиза.

Если тег уже запушен, а Release не создался — остановись и напиши оба факта. Тег не удаляй.

## Формат описания

Разделы строго в этом порядке: «Добавлено», «Изменено», «Удалено». Пустой раздел не выводи.

Скилл есть на `HEAD` и отсутствует в предыдущем теге — «Добавлено». Есть в предыдущем и отсутствует на `HEAD` — «Удалено». Есть в обоих, каталог изменился — «Изменено». Нет предыдущего тега — все текущие скиллы идут в «Добавлено».

Пункт «Добавлено» и «Изменено»: имя скилла — ссылка на `skills/<имя>/SKILL.md` в теге этой версии, затем ` — ` и одна фраза. Пункт «Удалено»: имя скилла без ссылки, затем ` — ` и одна фраза. Фраза по-русски, по diff этого скилла: что появилось, что изменилось или что удалено. Без списка коммитов и без перечня файлов.

Если предыдущий тег есть, последней строкой:

```markdown
**Full Changelog**: https://github.com/owner/repo/compare/ПРЕДЫДУЩИЙ...ВЕРСИЯ
```

Пример формы, не готовый текст релиза:

```markdown
## Добавлено

- [bro-example](https://github.com/owner/repo/blob/2.2.0/skills/bro-example/SKILL.md) — одна фраза, что появилось

## Изменено

- [bro-example](https://github.com/owner/repo/blob/2.2.0/skills/bro-example/SKILL.md) — одна фраза, что изменилось

## Удалено

- bro-old — одна фраза, что удалено

**Full Changelog**: https://github.com/owner/repo/compare/2.1.0...2.2.0
```

## Quality Control

Перед завершением проверь:

- тег указывает на тот `HEAD`, который проверялся;
- заголовок релиза равен версии из трёх манифестов;
- в «Добавлено» и «Изменено» у каждого пункта есть ссылка на `SKILL.md` этого тега, в «Удалено» ссылок нет;
- пустых разделов нет;
- человек видит URL релиза либо ясную причину остановки.

# CreatePlan

Workflow для режима планирования harness: спецификация оформляется и размещается тулом `CreatePlan` (или аналогом), без записи файла агентом.

## ОБЩИЕ ПРАВИЛА

- При составлении спецификации **ОБЯЗАТЕЛЬНО** соблюдай структуру разделов из [spec-template.md](../spec-template.md). Разделы «Правила frontmatter» и «Правила файла дельты» в шаблоне — канон оформления, **не** включай их в тело передаваемого содержимого.
- В содержимое, которое уходит в `CreatePlan`, **включай** YAML frontmatter с `readonly: false` и `is_implemented: false` (только эти два поля).
- Файл на диск **не** пиши; дельта `delta-<N>-<slug>.md` на диске создаётся только в workflow file-spec.

## ОГРАНИЧЕНИЯ / STOP

- **ЗАПРЕЩЕНО** после вызова `CreatePlan` предлагать следующий шаг.
- **ЗАПРЕЩЕНО** предлагать план реализации или `/bro-give-me-plan`.
- **ЗАПРЕЩЕНО** записывать `spec.md` или `delta-<N>-<slug>.md` на диск самому.

## ПОРЯДОК РАБОТЫ

1. **ПРОЧИТАЙ** [spec-template.md](../spec-template.md).
2. **ОПРЕДЕЛИ** содержимое: полная спека, обновление нереализованной спеки или дельта поверх реализованного `spec.md` — по тем же правилам, что в file-spec, но без записи на диск. Для дельты в тексте обязательна ссылка на `spec.md` того же каталога и только изменившиеся разделы; имя `delta-<N>-<slug>.md` собирай сам, у человека не спрашивай.
3. **ВЫЗОВИ** `CreatePlan` (или аналог harness для создания плана). Передай полное содержимое: frontmatter и тело по структуре шаблона. Если тул принимает заголовок/имя — укажи краткое название задачи. **НЕ ПИШИ** файл спецификации сам — harness оформит и разместит артефакт.

## Содержание спецификации

Спецификация в `CreatePlan` **ДОЛЖНА** содержать разделы:

- `Задача и контекст`
- `Целевой результат`
- `Принятые решения`
- `Рамки задачи`
- `Критерии приемки`

Раздел `Принятые решения` **МОЖЕТ** присутствовать только если есть зафиксированные договорённости. Иначе раздел **НЕ** создавай.

Для дельты передавай только изменившиеся из этого списка разделы плюс ссылку на `spec.md` каталога.

# File Spec

Workflow для спецификации как файлового артефакта.

## ОГРАНИЧЕНИЯ / STOP

- **ЗАПРЕЩЕНО** выбирать путь размещения файла спецификации самому.
- **ЗАПРЕЩЕНО** записывать файл спецификации до подтверждения полного пути человеком. Если файл уже существует — **ЗАПРЕЩЕНО** обновлять его без явного одобрения на обновление.

## ПОРЯДОК РАБОТЫ

1. **СПРОСИ** у человека полный путь файла спецификации. Путь **не** выбирай сам: даже если место кажется очевидным, **ЗАПРОСИ** его. Если файл по названному пути уже есть — прочитай его, **СООБЩИ** человеку и получи явное одобрение на обновление.
2. **СОЗДАЙ** или **ОБНОВИ** файл спецификации по шаблону и подтверждённому пути. Не жди отдельного апрува содержания перед записью.

## Quality Control

Перед завершением проверь:

- артефакт находится по подтверждённому человеком пути;
- путь был подтверждён человеком до первой записи;
- в артефакте есть все пять обязательных разделов и нет лишних, кроме допустимого `Принятые решения`;
- нет шагов, этапов и способа реализации;
- каждый изменяемый сценарий покрыт критерием приемки;
- каждый критерий содержит проверяемое доказательство;
- ревью выполнено по правилам (или явно пропущено человеком);
- при `NEEDS_WORK` файл обновлён, при `BLOCKED` задан вопрос человеку;
- `/bro-do-it` предложен только после `PASS` или явного пропуска ревью.

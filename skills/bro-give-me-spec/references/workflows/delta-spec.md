# Delta Spec

Workflow для правок спецификации.

## ПРАВИЛА WORKFLOW

- При составлении спецификации **ОБЯЗАТЕЛЬНО** соблюдай структуру разделов из [spec-template.md](../spec-template.md).
- После записи файла **ОБЯЗАТЕЛЬНО** проведи [ревью спецификации](../spec-review.md), если человек явно не попросил обойтись без ревью.
- Новый или изменённый результат фиксируй **не** правкой `spec.md`, а файлом рядом в каталоге `changes/<feature-id>/`. Имя: `delta-<N>-<slug>.md`, где `N` — наименьшее целое ≥ 1, которого ещё нет у файла `delta-<N>-*.md` в этом каталоге; `slug` — kebab-case из краткого смысла дельты. Имя у человека **не** спрашивай. Если каталог неизвестен — **СПРОСИ** путь к `spec.md` или к каталогу.
- **ЗАПРЕЩЕНО** пропускать ревью, кроме явной просьбы человека в текущем запуске.
- **ЗАПРЕЩЕНО** подменять вызов `/bro-review-spec-plan` собственной проверкой или своими субагентами-ревьюерами.
- **ЗАПРЕЩЕНО** после `NEEDS_WORK` снова вызывать `/bro-review-spec-plan`.
- **ЗАПРЕЩЕНО** предлагать составить план реализации, спецификация это самостоятельный артефакт.

## ПОРЯДОК РАБОТЫ

1. **ПРОЧИТАЙ** [spec-template.md](../spec-template.md).
2. **ОПРЕДЕЛИ** целевой артефакт:
   - прочитай `spec.md` в каталоге; если путь уже был в запросе — используй его; `spec.md` не переписывай;
   - `delta-<N>-<slug>.md`, если файл уже есть и правка относится к нему — **СООБЩИ** человеку и получи явное одобрение на обновление; иначе создай новый файл по правилу имени.
3. **СОЗДАЙ** или **ОБНОВИ** файл по шаблону. Для дельты включи ссылку на `spec.md` того же каталога (не на предыдущую дельту) и только изменившиеся разделы: разделы без изменения не создавай, неизменённое читается из `spec.md`. Не жди отдельного апрува содержания перед записью.
4. Если человек явно не просил пропустить ревью — **ВЫПОЛНИ** цикл по [правилам ревью](../spec-review.md) для записанного файла.
5. После завершения ревью (или после явного пропуска) **СООБЩИ** итог в чате. Отдельный апрув содержания не запрашивай: актуальный файл уже на диске.
6. Если ревью завершилось `PASS` или человек явно пропустил ревью — **ПОДСКАЖИ** единственный следующий шаг: `/bro-do-it`. Иначе следующий шаг не предлагай.

## Артефакты

### delta-<N>-<slug>.md

Дельта результата поверх `spec.md` в том же каталоге. Обязательна ссылка на `spec.md` каталога. Только изменившиеся разделы шаблона; критерии приёмки — только на дельту.

## Quality Control

Перед завершением проверь:

- если файл уже существовал — получено одобрение на обновление;
- в артефакте есть нужные разделы шаблона и нет лишних; у дельты есть ссылка на `spec.md`;
- каждый изменяемый сценарий покрыт критерием приемки;
- каждый критерий наблюдаем без описания способа проверки;
- независимое ревью доведено до `PASS` или `NEEDS_WORK` через `/bro-review-spec-plan` (или явно пропущено человеком);
- после `NEEDS_WORK` повторного `/bro-review-spec-plan` не было, замечания из этого списка закрыты;
- при `BLOCKED` задан вопрос человеку;
- после `PASS` или явного пропуска ревью предложен единственный следующий шаг: реализация с помощью `/bro-do-it`;

# Replenish — пополнение знаний проекта

Добавление и обновление постоянных знаний в хранилище, которое уже есть в проекте.

## ОБЩИЕ ПРАВИЛА

- **ОБЯЗАТЕЛЬНО** соблюдай [правила диалога](../references/dialog-rules.md)!
- **ОБЯЗАТЕЛЬНО** соблюдай [роли знаний](../references/knowledge-roles.md) и [правила содержимого](../references/content-rules.md)!
- **ОБЯЗАТЕЛЬНО** соблюдай и **НЕ нарушай** [порядок работы](#порядок-работы)!
- Перед записью **ПРОЧИТАЙ** существующие файлы по теме — не дублируй.
- Не спрашивай то, что можно установить с высокой уверенностью из уже загруженного контекста, сессии, переданной выжимки или прочитанных разделов.
- Не спрашивай, что именно добавить: либо пиши устойчивое знание, либо сообщи, что писать нечего.

## ОГРАНИЧЕНИЯ / STOP

- **ЗАПРЕЩЕНО** искать банк знаний по файловой системе.
- **ЗАПРЕЩЕНО** создавать и изменять рабочие артефакты задачи — это зона `/bro-give-me-spec` и `/bro-give-me-plan`.
- **ЗАПРЕЩЕНО** править generated-файлы молча; для записи контекста предлагай ручной слой или спрашивай путь.
- **ЗАПРЕЩЕНО** изобретать новый реестр, если у раздела его нет.
- **ЗАПРЕЩЕНО** придумывать факты. Только подтверждённая информация.
- **ЗАПРЕЩЕНО** отправлять к `/bro-init-memory-bank`, если разделы не найдены.
- **ЗАПРЕЩЕНО** писать в `AGENTS.md` или другой файл инструкций проекта без согласия человека.

## ПОРЯДОК РАБОТЫ

1. **ОПРЕДЕЛИ** разделы по [ролям знаний](../references/knowledge-roles.md). Источник — только уже загруженный контекст (`AGENTS.md`, правила и аналоги). Если раздел не виден — **ОСТАНОВИСЬ** и спроси путь у человека. Недостающий раздел можно предложить создать по указанному пути.
2. **ПРОЧИТАЙ** релевантные файлы в привязанных разделах по запросу, сессии и переданной выжимке.
3. **КЛАССИФИЦИРУЙ** знание по [правилам содержимого](../references/content-rules.md). Если писать нечего — **СООБЩИ** это человеку и **ЗАВЕРШИ** без правок файлов.
4. **ПРОВЕРЬ**, нет ли уже файла или подраздела по этой теме. Если есть — обновляй его, не создавай дубликат.
5. **ЗАПИШИ** сразу. Если у раздела уже есть реестр — обнови его при новой записи или переименовании. Для контекста из generated-слоя пиши в ручной слой или спроси путь записи.
6. **ПОКАЖИ** человеку: что изменилось, какие файлы затронуты, нужны ли ещё уточнения. Если карту разделов спрашивали впервые — **РЕКОМЕНДУЙ** сохранить три пути в `AGENTS.md` или другом файле инструкций проекта; не пиши туда без согласия.

## Обновление vs создание

| Ситуация | Действие |
|---|---|
| Тема уже есть в разделе контекста | Дополни или исправь существующий файл |
| Фича уже описана в разделе features | Обнови существующий файл |
| Новая фича | Создай файл в разделе features; обнови реестр, если он уже есть |
| Новая процедура | Создай файл в разделе playbooks; обнови реестр, если он уже есть |
| Сквозное решение | Новая запись в файле решений в разделе контекста (если такого файла нет — создай его в этом разделе) |

## Критерии завершения

- Устойчивое знание записано в правильный раздел без дублей **или** человеку сказано, что писать нечего, и файлы не тронуты.
- Перед записью не было стопа с черновиком.
- Реестр обновлён только если уже существовал у раздела.
- Рабочие артефакты задачи (спецификация результата, план работ) не затронуты.

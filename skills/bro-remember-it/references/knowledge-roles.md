# Роли знаний

Скилл держит **роли**, а не дерево каталогов. Пути к контексту, фичам и playbooks берутся из уже загруженного контекста агента (`AGENTS.md`, правила проекта и аналоги). Для этих трёх ролей дефолтного корня нет.

## Разделы

| Роль | Смысл | Примеры содержимого |
|---|---|---|
| Контекст проекта | Долгоживущие сведения о продукте, стеке, архитектуре, нормах, глоссарии, сквозных решениях | overview, tech-stack, architecture, conventions, glossary, decisions |
| Features | Данные по фичам: границы, поведение, решения по фиче | описание фичи, статус, сценарии |
| Playbooks | Конкретные пошаговые типовые инструкции | «когда применять», предусловия, шаги, проверка |
| Намерения | Будущее действие или идея, которая ещё не стала решением о продукте | одна формулировка, приложенный файл |

## Путь намерений

У намерений путь фиксированный. Его не спрашивают и не ищут по дереву.

Корень банка — тот, что уже назван в контексте. Если корень не назван — `memory-bank/`. Запись — `<корень>/todos/<slug>/todo.md`.

Контексту, фичам и playbooks этот путь не навязывай. Не делай `/bro-init-memory-bank` обязательным шагом.

## Что считать разделом

Правила ниже — про контекст, фичи и playbooks. Намерение по ним не останавливай: его путь задан выше.

Раздел привязан, если в уже загруженных инструкциях однозначно видно, **куда** относятся знания этой роли (каталог, файл или явная ссылка в карте документов).

- **ЗАПРЕЩЕНО** искать банк знаний по файловой системе (`find`, `glob`, обход дерева «на всякий случай»). Чтение уже известного каталога `<корень>/todos/` при записи намерения — не поиск.
- Если роль контекста, фичи или playbook не видна в контексте — **ОСТАНОВИСЬ** и спроси путь у человека.
- Недостающий раздел можно предложить создать по указанному человеком пути. Не навязывай канон `memory-bank/` и не делай `/bro-init-memory-bank` обязательным шагом.

## Реестр

Если рядом с разделом уже есть реестр (`index.md`, README раздела, секция «Связанные документы» в `AGENTS.md` и т.п.) — обновляй его при добавлении или переименовании файла в этом разделе.

**ЗАПРЕЩЕНО** изобретать новый канонический `index.md`, если реестра у раздела нет.
**МОЖНО** рекомендовать его создать, если есть такая необходимость.
Для намерений реестр не создавай и не предлагай.

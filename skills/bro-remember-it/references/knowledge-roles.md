# Роли знаний

Скилл держит **роли**, а не дерево каталогов. Пути к разделам берутся из уже загруженного контекста агента (`AGENTS.md`, правила проекта и аналоги). Дефолтного корня банка нет.

## Три раздела

| Роль | Смысл | Примеры содержимого |
|---|---|---|
| Контекст проекта | Долгоживущие сведения о продукте, стеке, архитектуре, нормах, глоссарии, сквозных решениях | overview, tech-stack, architecture, conventions, glossary, decisions |
| Features | Данные по фичам: границы, поведение, решения по фиче | описание фичи, статус, сценарии |
| Playbooks | Конкретные пошаговые типовые инструкции | «когда применять», предусловия, шаги, проверка |

## Что считать разделом

Раздел привязан, если в уже загруженных инструкциях однозначно видно, **куда** относятся знания этой роли (каталог, файл или явная ссылка в карте документов).

- **ЗАПРЕЩЕНО** искать банк знаний по файловой системе (`find`, `glob`, обход дерева «на всякий случай»).
- Если роль не видна в контексте — **ОСТАНОВИСЬ** и спроси путь у человека.
- Недостающий раздел можно предложить создать по указанному человеком пути. Не навязывай канон `memory-bank/` и не делай `/bro-init-memory-bank` обязательным шагом.

## Реестр

Если рядом с разделом уже есть реестр (`index.md`, README раздела, секция «Связанные документы» в `AGENTS.md` и т.п.) — обновляй его при добавлении или переименовании файла в этом разделе.

**ЗАПРЕЩЕНО** изобретать новый канонический `index.md`, если реестра у раздела нет.
**МОЖНО** рекомендовать его создать, если есть такая необходимость.

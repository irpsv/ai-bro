# Git при закрытии

Вызов `/bro-finish-it` — запрос человека создавать коммиты закрытия и пушить текущую ветку. Отдельное подтверждение на сам факт коммита и пуша **не** спрашивай, если состав файлов однозначен.

## Состояние

Сними снимок до любых git-записей:

- есть ли репозиторий;
- текущая ветка;
- незакоммиченные изменения;
- неотправлённые коммиты;
- есть ли remote.

Если репозитория нет — git-шаги пропусти, сообщи об этом и переходи к знаниям. Удаление временных артефактов в этом случае **не** выполняй: их нет в истории git.

Если detached HEAD, незавершённый merge/rebase или конфликт — **ОСТАНОВИСЬ** и спроси человека.

## Что коммитить

В коммит работы входят только файлы текущей задачи.

**НЕ** включай:

- секреты и локальные служебные файлы;
- посторонние изменения грязного дерева;
- файлы из [списка временных артефактов](./temp-artifacts.md) — их удаляют отдельным шагом после знаний.

Если в грязном дереве есть и файлы задачи, и посторонние либо неочевидные пути — **ОСТАНОВИСЬ** и спроси, что входит в коммит. Не коммить «всё подряд».

Не создавай пустой коммит. Если незакоммиченных изменений задачи нет — этот шаг пропусти.

После `/bro-remember-it` и удаления временных файлов зафиксируй оставшиеся незакоммиченные изменения закрытия (запись знаний и/или удаление артефактов) одним коммитом, если они есть.

## Как коммитить и пушить

- Не меняй git config.
- Не используй `--amend`, `--no-verify`, `--no-gpg-sign`, force push и интерактивные git-команды.
- Не пропускай хуки.
- Сообщение — кратко, в стиле репозитория: коммит работы — о сути изменения; коммит закрытия — о записи знаний и/или удалении временных артефактов.
- Пушь текущую ветку. Если ветка ещё не связана с remote — `git push -u`.
- Если remote нет или пуш не удался — сообщи причину и продолжай локальное закрытие. Не считай remote закрытым.

## PR/MR

Пуш сам по себе не открывает запрос на слияние.

Предложи создать PR/MR **только** если текущая ветка не `main` и не `master` и запроса на слияние для этой ветки ещё нет. На `main`/`master` или если PR/MR уже есть — этот пункт не предлагай.

Создавай PR/MR **только** после явного согласия человека. Без согласия не вызывай `gh` / аналоги.

# code-exploration

Правила анализа репозитория через субагентов.
Оркестратор ведёт диалог и синтез; чтение и разбор кода уходят в отдельные контексты.

## Когда запускать explorer

**ОБЯЗАТЕЛЬНО** делегируй анализ субагенту explorer, если из контекста разговора нельзя сделать нужные выводы и требуется анализ репозитория.

**ЗАПРЕЩЕНО** анализировать репозиторий самому в контексте оркестратора, если доступен субагент explorer.
**ЗАПРЕЩЕНО** запускать explorer, когда выводов из разговора уже достаточно.

Если harness не поддерживает субагентов, читай репозиторий сам и сразу своди результат к краткой выжимке, не таща сырые чтения дальше по диалогу.

## Как оркестрировать

1. Сформулируй, каких выводов не хватает и какие области репозитория нужно проанализировать.
2. Разбей анализ на независимые области по одному модулю или подсистеме на запуск, если областей несколько.
3. Для каждого запуска сформируй полный task payload и выбери тир модели до вызова `Task`.
4. Независимые области запускай параллельно.
5. В `Task` передай текст промпта explorer и payload целиком. Не ссылайся на внутренние файлы скилла.
6. После ответов синтезируй выводы сам: диалог, вопросы пользователю и выбор следующего шага остаются у оркестратора.

## Task payload

В каждый запуск explorer подставь:

```text
Вопрос или гипотеза: <что нужно прояснить>
Область изучения: <модуль, каталог, подсистема или набор путей>
Зачем оркестратору результат: <как выжимка будет использована>
Известный контекст: <только факты, уже нужные для фокуса; без истории всего диалога>
Ограничения: READONLY; без предложений реализации и плана
```

## Выбор тира

- [simple](./subagent-model-tiers.md#simple) — краткая выжимка по области, список сущностей, извлечение фактов.
- [coding](./subagent-model-tiers.md#coding) — объяснить поведение по исходникам, конфигам и цепочкам вызовов внутри области.

## После ответов субагентов

1. Оставь в рабочем контексте только выжимки, а не сырые чтения субагентов.
2. Склей пересечения и отбрось дубли.
3. При противоречии запусти повторный explorer с уточнённым payload.
4. Не пересказывай пользователю внутренние отчёты целиком — используй их для прояснения и одного следующего шага.

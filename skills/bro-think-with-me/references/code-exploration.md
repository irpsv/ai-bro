# code-exploration

Правила глубокого изучения репозитория через субагентов.
Оркестратор ведёт диалог и синтез; сырое чтение кода уходит в отдельные контексты.

## Когда запускать explorer

**ОБЯЗАТЕЛЬНО** делегируй изучение субагенту explorer, если для ответа нужно глубоко читать код и выполняется хотя бы одно:

- предстоит разобрать два и более модуля, подсистемы или крупных каталога;
- область чтения широкая: много файлов, длинные цепочки вызовов, несколько слоёв;
- параллельно нужно изучить независимые области.

**Допустимо** читать самому без субагента, если:

- достаточно разговора, уже известных фактов или короткой карты структуры;
- нужен один небольшой файл, символ или узкий фрагмент;
- harness не поддерживает субагентов — тогда читай последовательно сам и сразу своди к краткой выжимке, не таща сырые чтения дальше по диалогу.

**ЗАПРЕЩЕНО** заводить субагента для поиска в интернете или обзора внешних статей.
**ЗАПРЕЩЕНО** запускать explorer «на всякий случай», когда глубокое чтение кода ещё не нужно.

## Как оркестрировать

1. Сначала сам собери лёгкую карту: структура, точки входа, какие модули вообще релевантны вопросу.
2. Разбей изучение на независимые области по одному модулю или подсистеме на запуск.
3. Для каждого запуска сформируй полный task payload и выбери тир модели до вызова `Task`.
4. Независимые области запускай параллельно.
5. В `Task` передай текст промпта explorer и payload целиком. Не ссылайся на внутренние файлы скилла.
6. После ответов синтезируй выводы сам: диалог, вопросы пользователю и выбор следующего шага остаются у оркестратора.

## Task payload

В каждый запуск explorer подставь:

```text
Вопрос или гипотеза: <что нужно прояснить>
Область изучения: <модуль, каталог, подсистема или набор путей>
Зачем оркестратору результат: <как выжимка будет использована>
Известный контекст: <только факты, уже нужные для фокуса; без истории всего диалога>
Ограничения: READONLY; без интернета; без предложений реализации и плана
```

## Выбор тира

- [simple](./subagent-model-tiers.md#simple) — краткая карта модуля, список сущностей, извлечение фактов по узкой области.
- [coding](./subagent-model-tiers.md#coding) — объяснить поведение по исходникам, конфигам и цепочкам вызовов внутри области.

## После ответов субагентов

1. Оставь в рабочем контексте только выжимки, а не сырые чтения субагентов.
2. Склей пересечения и отбрось дубли.
3. При противоречии либо точечно перепроверь сам узкий фрагмент, либо запусти повторный explorer с уточнённым payload.
4. Не пересказывай пользователю внутренние отчёты целиком — используй их для прояснения и одного следующего шага.

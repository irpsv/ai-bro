# subagent-model-tiers

Единый словарь тиров мощности и семейств моделей.
Этот файл описывает не slug-и конкретного harness, а семейства в формате `vendor/model-family`. Роль субагента задаётся его промптом и не определяет тир. Сначала выбери минимальный достаточный тир по сложности, неоднозначности и риску задачи, затем семейство модели внутри этого тира.

## Общие правила

1. Для каждого запуска субагента сначала определи минимальный достаточный тир по правилам вызывающего скилла или workflow, затем выбери семейство модели внутри этого тира.
2. Семейства моделей внутри каждого тира перечислены в порядке приоритета. Всегда выбирай первое доступное семейство из списка выбранного тира.
3. Если семейство недоступно в текущем harness, переходи к следующему семейству по списку в рамках того же тира.
4. Повышай тир только по явному правилу вызывающего скилла или workflow: из-за сложности, риска либо результата предыдущей попытки. Недоступность семейства сама по себе не является основанием для повышения.
5. Если ни одно семейство выбранного тира недоступно, используй либо **auto** режим, либо текущую **inherit** модель.
6. Не понижай тир, явно заданный вызывающим скиллом или workflow.
7. После выбора тира выбери целевую глубину размышлений (`reasoning` / `thinking`) для этого тира.
8. Канонические уровни глубины размышлений в этом файле: `low`, `balanced`, `deep`.
9. Глубина размышлений зависит от модели. Используй только те параметры, варианты или отдельные model ID, которые реально поддерживает выбранная модель в текущем harness.
10. `low` означает минимальную глубину размышлений, если она поддерживается моделью.
11. `balanced` означает `medium`, если такой уровень есть у модели, иначе обычный режим без принудительного `high`.
12. `deep` означает максимальную доступную глубину размышлений, например `high`, thinking variant или другой усиленный режим модели.
13. Если модель не поддерживает настройку глубины размышлений, используй её обычный режим и не меняй тир из-за отсутствия такой настройки.

## senior

Используй для сложных, неоднозначных или высокорисковых задач, а также когда менее мощный тир не дал результата:

- провести архитектурный или системный анализ;
- разрешить конфликтующие ограничения и нетривиальные компромиссы;
- работать с конкурентностью или критическими публичными контрактами вне узкого контура `critical`;
- критически проверить сложное решение;
- продолжить работу после неуспешной попытки на `middle`.

Целевая глубина размышлений: `deep`.

Подходящие модели:

1. `cursor/grok`
2. `openai/gpt`
3. `anthropic/claude-opus`

## critical

Используй только для узкой независимой проверки безопасности отдельным субагентом. Не применяй этот тир к обычным профильным ревью (`requirements`, `correctness`, `performance`, `tests`), общей разработке, verifier или исследованию кода.

- проверить безопасность: границы доверия, аутентификацию, авторизацию, секреты, недоверенный ввод.

Целевая глубина размышлений: `deep`.

Подходящие модели:

1. `openai/gpt-sol`
2. `anthropic/claude-fable`

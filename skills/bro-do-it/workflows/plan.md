# plan

Используй этот режим, когда входной файл задаёт способ или порядок реализации — то есть описывает, **как** выполнять задачу.

## Правила

- Прочитай файл полностью и считай его неизменяемым источником истины.
- Строго соблюдай заданные шаги, порядок, технический подход, рамки и критерии приемки.
- Самостоятельно выбирай только детали, которых план не определяет и которые не меняют его способ реализации.
- Не исправляй, не нормализуй и не обновляй план, включая служебные статусы.
- Если имя и содержимое файла противоречат друг другу, план неоднозначен или его нельзя выполнить как написано, остановись и задай человеку один конкретный вопрос.

## Task payload

Передай developer полный контекст текущей единицы работы:

```text
Режим: PLAN
Файл плана: <путь>
Цель и рамки: <точные формулировки из плана>
Обязательный способ и порядок: <относящиеся к текущей работе инструкции плана без смыслового пересказа>
Текущая единица работы: <шаги или связный инкремент>
Критерии приемки: <точные критерии>
Ограничения: <ограничения и запреты>
Проверки: <заданные планом и стандартные проверки проекта>
```

Для следующей волны сохрани исходный payload и добавь только невыполненные критерии, ошибки проверок, обязательные замечания ревью и минимальный контекст предыдущей попытки.

# generic-plan

Реализация задачи по **файлу спецификации или плана** в произвольном формате.

Формат файла заранее не гарантирован. Файл воспринимается как артефакт задачи; структуру **не парси** и **не нормализуй**.

## Основные правила

- СНАЧАЛА **прочитай** файл-артефакт, чтобы понять задачу, рамки и критерии приемки.
- Файл-артефакт — **источник истины** для task payload. Не пересказывай его содержимое своими словами, если достаточно ссылки на файл.
- Если неизвестен пользовательский результат, рамки или критерии приемки, остановись и запроси уточнение у пользователя. Технические неоднозначности разрешай самостоятельно по принципу автономности основного процесса.
- Результат workflow — **task payload** для подстановки в `<task payload>` промптов developer и reviewer.

## Task payload

```
Реализуй задачу по артефакту спецификации или плана: </path/to/artifact.md>
Считай этот файл основным контекстом задачи.
Не изменяй артефакт во время исполнения.
Технические неоднозначности, которые не меняют пользовательский результат, разрешай самостоятельно консервативным способом по существующему коду.
Для каждого критерия приемки предоставь соответствие «реализация → доказательство». Изменяемое поведение покрой уместными автоматизированными тестами; TDD не требуется, если он явно не задан в артефакте.
Верни блокер родителю только если неизвестен или изменится пользовательский результат, публичный контракт либо продуктовая логика; возникнет риск для данных или безопасности; потребуется платный или необратимый внешний эффект, секрет, доступ, юридическое или организационное решение; либо задача противоречит ограничениям репозитория.
```

Для reviewer используй тот же payload.

Синхронизация шагов **не выполняется**.

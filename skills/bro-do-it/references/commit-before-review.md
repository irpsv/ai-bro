# Коммиты

Вызов `/bro-do-it` — запрос человека создавать эти коммиты. Не спрашивай отдельного подтверждения.

Verifier и closer коммиты не создают.

## Developer

После реализации своего назначения developer сам коммитит только свои правки, до возврата отчёта родителю.

Коммит обязателен и тогда, когда гейт проверок родителя потом завернут инкремент: так видна история, до чего докапываются проверки, и проще откатиться к рабочему варианту.

Не создавай пустой коммит. Если незакоммиченных правок назначения нет, коммит не нужен.

Если git-репозитория нет, работай без коммита.

## Оркестратор после `/bro-remember-it`

После вызова `/bro-remember-it` оркестратор коммитит только файлы, которые этот вызов записал.

Не создавай пустой коммит. Если записей не было, коммит не нужен.

## Что входит

Только файлы текущего назначения: у developer — его правки, у оркестратора — записи `/bro-remember-it`. Не включай посторонние изменения грязного дерева, секреты и локальные служебные файлы.

## Как

- Не меняй git config.
- Не используй `--amend`, `--no-verify`, `--no-gpg-sign`, force push и интерактивные git-команды.
- Не пушь.
- Не пропускай хуки.
- Сообщение — кратко, в стиле репозитория, о сути инкремента. Для developer укажи номер итерации разработки. Не помечай коммит как незавершённый только потому, что проверки или ревью ещё не прошли.
- Если коммит developer не создался при незакоммиченных правках назначения, не считай работу завершённой.
- Если после developer остались незакоммиченные изменения его назначения, не вызывай closer и ревью.

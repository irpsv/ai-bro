# Повторное ревью после итерации

Исходная база задачи и точка последнего ревью — разные отметки.

- **Исходная база задачи** фиксируется до любых изменений и дальше не сдвигается. Её использует verifier для всей задачи.
- **Точка последнего ревью** сначала совпадает с исходной базой. После каждого вызова `/bro-review-code` сдвигается на текущий HEAD.

## Список обязательных замечаний

Оркестратор держит открытый список обязательных замечаний последнего ревью: `critical`, `high` и блокирующие приемку `medium`.

При появлении такого ревью:

- присвой каждому пункту стабильный идентификатор (`F-001`, `F-002`, …);
- сохрани серьёзность, место, проблему и требуемое исправление без смыслового пересказа;
- этот список заменяет предыдущий.

Пустой список — обязательных замечаний нет. Невыполненные критерии приемки из ревью входят в тот же список.

После ревью без обязательных замечаний и с выполненными критериями очисти список.

## Вызов `/bro-review-code`

Всегда передавай:

- объект ревью — изменения после точки последнего ревью;
- базу сравнения — точку последнего ревью;
- контекст задачи и результаты быстрых проверок.

Не передавай на повторное ревью все изменения задачи относительно исходной базы, если точка последнего ревью уже сдвинута.

После вызова обнови точку последнего ревью на текущий HEAD, даже если появились новые обязательные замечания.

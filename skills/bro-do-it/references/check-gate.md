# Гейт проверок

Шаг после developer и до closer/ревью. Это шлагбаум «не тащить на ревью сломанное дерево», а не независимая приёмка. Независимый прогон тестов делает verifier.

## Когда принять доказательства developer

Прими отчёт и не перезапускай те же команды, если выполняется всё:

- в этой итерации был один developer, либо назначения не собирались в общее дерево;
- для каждой релевантной проверки есть команда и фактический исход: код выхода или короткий хвост вывода. Голого «тесты прошли» недостаточно;
- набор покрывает изменённую область, а не один случайный тест;
- снимок совпадает с текущим HEAD назначения: проверки после коммита либо сразу перед ним, без правок между проверкой и коммитом.

Пропущенная проверка допустима только с краткой причиной, которую ты принимаешь.

## Когда запустить проверки самому

Выполни недостающие быстрые релевантные проверки по текущему дереву, если есть хотя бы одно:

- нет команды и фактического исхода;
- набор уже, чем нужно для изменённой области;
- в итерации было несколько developer — проверяй уже собранное дерево;
- после указанных проверок появились новые коммиты назначения или незакоммиченные правки назначения;
- developer не запускал проверку без причины, которую ты принимаешь.

Не расширяй гейт до полной приёмки по всем критериям и ветвям. Не гоняй заново те же команды при достаточных доказательствах.

## Ошибка гейта

Считай ошибкой и возвращай developer:

- незакоммиченные изменения назначения;
- падение принятых или повторно запущенных проверок.

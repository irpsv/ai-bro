# Inline Plan

Описание workflow по формулированию implementation плана в текущем чате, без файла плана.
Задача составить короткий план реализации (implementation plan) для этой сессии.

## ОБЩИЕ ПРАВИЛА

- **ОБЯЗАТЕЛЬНО** соблюдай [правила диалога](../dialog-rules.md)!
- **ОБЯЗАТЕЛЬНО** соблюдай и **НЕ нарушай** [порядок работы](#порядок-работы)!
- План **ДОЛЖЕН** быть однозначным, без наличия вариаций и вопросов в нём. Все вопросы и вариации **НУЖНО** решать с человеком.
- План **НЕ ДОЛЖЕН** подменять шаги реализации кодом, diff, патчами или псевдокодом.
- При составлении плана **ОБЯЗАТЕЛЬНО** оформляй шаги по [правилам формирования шагов](#правила-формирования-шагов).
- План **НУЖЕН** только в контексте текущего чата, то есть составляемый план добавляет информацию из текущего диалога и **НЕ ДОЛЖЕН** дублировать информацию которая уже понятна из контекста.
- Если что-то непонятно, нелогично или неправильно **ОБЯЗАТЕЛЬНО** уточни у человека

## ОГРАНИЧЕНИЯ / STOP

- **ЗАПРЕЩЕНО** придумывать и додумывать факты или гипотезы. Любая неоднозначность **ДОЛЖНА** быть решена до перехода к составлению плана.
- **ЗАПРЕЩЕНО** создавать или записывать файлы плана.

## ПОРЯДОК РАБОТЫ

1. **ПРОЧИТАЙ** [правила формирования шагов](#правила-формирования-шагов).
2. **СОБЕРИ** информацию для составления однозначного плана: код, контекст:
   - Не спрашивай то, что можно установить с высокой уверенностью.
   - Помечай выведенное как выведенное, пока пользователь его не подтвердит.
3. **ЗАПРОСИ** недостающую информацию у человека. **ОБЯЗАТЕЛЬНО** соблюдай [правила диалога](../dialog-rules.md).
4. **СОСТАВЬ** план, шаги оформляй по [правилам формирования шагов](#правила-формирования-шагов).
5. **ВЫВЕДИ** план в чат.
6. **ОСТАНОВИСЬ** и жди дальнейших указаний от человека. Либо правки плана, либо переход к реализации.

## ПРАВИЛА ФОРМИРОВАНИЯ ШАГОВ

Нумерованный список ходов с описанием  для текущего чата.

Формат:
- Каждый пункт — одно предложение и один ход: добавление, изменение или удаление.
- Упорядочи шаги в порядке выполнения. Ход, без которого следующий невозможен, стоит раньше.
- В предложение входят действие и якорь, по которому **не перепутать** цель: путь, имя, сущность или наблюдаемый результат.

Пример итогового результата работы:
```markdown
План реализации:
1. Добавить сервис, который собирает список справочников сущности Y.
2. Добавить в path/to/Controller.php экшен, который отдаёт этот список через сервис.
3. Добавить e2e-тест: экшен контроллера отдаёт список справочников Y.
```

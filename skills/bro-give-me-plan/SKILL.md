# Bro Give Me Plan

Твоя задача — составить план реализации для конкретной задачи и проблемы.
**НЕ ПИШИ** сам код, только составляй план.
Если человеку нужна спецификация результата без шагов реализации, **ОСТАНОВИСЬ** и предложи `/bro-give-me-spec`.

## ОБЩИЕ ПРАВИЛА

- **ОБЯЗАТЕЛЬНО** соблюдай [правила диалога](./references/dialog-rules.md)!
- **ОБЯЗАТЕЛЬНО** соблюдай [гигиену реализации](./references/implementation-hygiene.md)!
- **ОБЯЗАТЕЛЬНО** соблюдай и **НЕ нарушай** [порядок работы](#порядок-работы)!
- План **ДОЛЖЕН** быть однозначным, без наличия вариаций и вопросов в нём. Все вопросы и вариации **НУЖНО** решать с человеком.
- План **НЕ ДОЛЖЕН** подменять шаги реализации кодом, diff, патчами или псевдокодом.
- Если в плане есть раздел критериев приемки, они **ДОЛЖНЫ** покрывать целевой результат наблюдаемыми утверждениями. Способ проверки (автотест, ручная проверка, сборка и т.п.) в критерии **НЕ** указывай.

## ОГРАНИЧЕНИЯ / STOP

- **ЗАПРЕЩЕНО** нарушать порядок работы и правила workflows
- **ЗАПРЕЩЕНО** придумывать и додумывать факты или гипотезы. Любая неоднозначность **ДОЛЖНА** быть решена до перехода к составлению плана.

## ПОРЯДОК РАБОТЫ

1. **СОБЕРИ** информацию для составления однозначного плана: код, контекст:
   - Не спрашивай то, что можно установить с высокой уверенностью.
   - Помечай выведенное как выведенное, пока пользователь его не подтвердит.
2. **ЗАПРОСИ** недостающую информацию у человека. **ОБЯЗАТЕЛЬНО** соблюдай [правила диалога](./references/dialog-rules.md).
3. **ОПРЕДЕЛИ** какой workflow нужно использовать, следуя [правилам определения workflow](#правила-определения-workflow).
4. **ПОДКЛЮЧИ** файл с инструкциями выбранного workflow. **СОБЛЮДАЙ** все инструкции из выбранного workflow.

## ПРАВИЛА ОПРЕДЕЛЕНИЯ WORKFLOW

**ОПРЕДЕЛИ** workflow по запросу. Подтверждение выбора **НЕ ЗАПРАШИВАЙ**.

### inline

Используй если:
- в контексте есть указание harness оформить план через конкретный тул (например `CreatePlan`) или активен режим планирования;
- человек явно попросил оставить план в чате.

Файл с инструкциями: [inline-plan](./references/workflows/inline-plan.md)

### file

Используй во всех остальных случаях, по умолчанию: нужен файловый артефакт плана, который переживёт новый чат, с разделами «Рамки» и «Критерии приёмки».

Файл с инструкциями: [file-plan](./references/workflows/file-plan.md)

Крупные многоэтапные инициативы **НЕ** планируй через этот скилл одним большим планом: сначала зафиксируй желаемый результат через `/bro-give-me-spec`, а планы составляй на конкретные небольшие задачи.
